# 🏛️ 中国传媒大学 侵权商品检测系统

自动搜索淘宝"中国传媒大学"相关商品，智能识别非书籍类侵权商品，进入详情页截图，生成 Excel 报告（含嵌入截图）。  
支持 **DeepSeek AI 侵权校验**，对商品进行精确到每一分的侵权评分。

> 💡 **无需任何 API Key 即可使用基础检测功能**，AI 校验为可选增强模块。

## 🚀 部署与使用完整指南

> 本章是**从零到跑起来**的完整步骤。首次部署请**按顺序**做完 ①~⑤，之后每次使用只需看 ⑥。

### ① 拷贝项目

把整个 `cuc-trademark-detector` 文件夹拷到目标机器任意路径（路径**不要含中文以外的特殊字符**，建议 `D:\cuc-trademark-detector`）。

> 💡 项目自带 `start.bat` + `check_env.py`，**不需要**手动装环境变量、不需要配 PATH。

### ② 创建 conda 环境（必须，一次性）

打开 **Anaconda Prompt**，执行：

```bat
conda create -n pyExcel python=3.9 -y
conda run -n pyExcel pip install playwright openpyxl requests
```

> ⚠️ **为什么必须用 `pyExcel` 这个环境名？**
> 不同 playwright 版本要求的 chromium 版本号不同（1.60 → `chromium-1223`，1.61 → `chromium-1228`）。
> `start.bat` 会**强制定位 `pyExcel`**，找不到就明确报错退出，**不会**静默回退到 base/系统 Python
> ——否则会报出难懂的 `Executable doesn't exist ... chromium_headless_shell-xxxx`。
>
> `start.bat` 的查找顺序（**不依赖任何个人机器路径**）：
> ① `%CONDA_PREFIX%\..\envs\pyExcel` → ② `conda run -n pyExcel` → ③ `%CONDA_ROOT%\envs\pyExcel`
> → ④ 扫描常见 Anaconda/Miniconda 安装位置（`%USERPROFILE%\anaconda3`、`C:\ProgramData\anaconda3` 等）。
>
> 如果你的 conda 装在非常规位置，二选一：环境改名成 `pyExcel`，或在 `start.bat` 第 4 步的候选列表里加上你的路径。

### ③ 下载浏览器（首次，二选一）

**方案 A（推荐，零下载）：用系统已装的 Edge**

只要本机是 Windows 10/11 且装过 Edge，`start.bat` 会**自动检测并直接使用**，无需任何操作。

**方案 B（无 Edge 时）：下载项目内置 Chromium**

```bat
set PLAYWRIGHT_BROWSERS_PATH=%~dp0.playwright-browsers
conda run -n pyExcel python -m playwright install chromium

### 常见问题

**Q: 报错 `Executable doesn't exist ... chromium_headless_shell-xxxx`？**

```

**Q: 价格显示成"已售592件"里的数字（如 5元显示592）？**

该 Bug 已修复（见下方"价格提取规则"）。如仍出现，请删除 `data/logs/detector.log` 后重跑并反馈。

**Q: 价格小数位丢了（5.32 显示成 5，4.70 显示成 4）？**

该 Bug 已在 2026-09 修复（两轮）。原因是价格容器定位有两处缺陷：

1. `querySelector('[class*="price"]')` 会直接命中 `<span class="priceInt">5</span>` 这个**最内层叶子节点**，导致内部查不到兄弟节点里的 `.32`
2. **当 `priceInt`/`priceDec` 直接作为卡片子元素时**（无独立价格容器），最低公共祖先算法退化成返回 `priceInt` 叶子本身，小数位仍会丢失

现在 `findPriceRoot()` 会：① 计算含自身的**最低公共祖先**；② 优先取"内含 `priceInt`/`priceDec` 的最深容器"；③ 若公共祖先就是叶子本身，**上溯到父节点**；④ 最差情况给容器打 `__priceScoped` 标记返回卡片，此时**禁用整体文本兜底**（否则标题里的数字会被拼进价格，`88.5`→`788.5`）。

若本地仍拿不准，会**自动调用 AI 复核**（见下节）。

## 💰 价格提取规则

淘宝价格区常与销量混在一个容器里（如 `¥5.00 592人付款`），若直接取数字会把**销量误当价格**。

### 四层处理流程

**第 1 层：定位真正的价格容器**（`findPriceRoot`）

不能直接用 `querySelector('[class*="price"]')` —— 它会命中 `<span class="priceInt">5</span>` 这种最内层叶子，导致小数位 `.32` 丢失。程序改为：

1. 收集卡片内所有类名含 `price/Price/g_price` 的元素（排除销量类）
2. **只有一个候选** → 直接返回（如 `<div class="priceBox">¥88.50</div>`）
3. 若存在"内含 `priceInt`/`priceDec` 的元素" → 取其**最深**的那个
4. 否则计算所有候选的**最低公共祖先**（`ancestorsOf` **包含元素自身**，这样 `priceInt` 与 `priceDec` 是兄弟时，公共祖先 = 它们共同的父节点）
5. 若公共祖先就是候选叶子本身 → **上溯到父节点**（关键：否则 `querySelectorAll('[class*="priceDec"]')` 不含自身，查不到小数位）
6. 最差兜底 → 返回 `scope` 并打 `__priceScoped` 标记，`extractPriceFromContainer` 会**禁用整体文本兜底**

**第 2 层：拼接价格**（`extractPriceFromContainer`）

1. **优先** `priceInt` + `priceDec` 精确拼接（`5` + `.32` → `5.32`）
   - 小数位查找兜底：若没有 `priceDec`，则取 `priceInt` 的**下一个兄弟节点**（兼容 `class="dec--b"` 这类无 price 字样的类名）
   - 兼容 `priceInt` 自带小数（`5.32` 全在一个 span 里）与千分位（`1,299` + `.00`）
2. **其次** 逐个候选元素校验，跳过容器/销量元素；**优先返回带小数位的结果**，避免整数抢先返回
3. **兜底** 用容器整体文本（`extractPrice` 内部已剔除销量片段）
   - ⚠️ 若容器带 `__priceScoped` 标记（价格元素直接挂在卡片下），**跳过此步**——卡片文本含标题，标题数字会被拼进价格（`88.5` → `788.5`）

**第 3 层：AI 辅助复核**（`resolve_price` / `verify_price_by_ai`）

本地规则拿不准时自动调 DeepSeek 复核，触发条件（可在 `backend/config.py` 关闭）：

| 条件 | 说明 |
|---|---|
| 本地未提取到价格，但价格区有原文 | 让 AI 尝试兜底 |
| 价格区原文含**有效小数**，但结果无小数位 | 疑似小数被截断（`5.32`→`5`）；`¥128.00` 这类尾随零不算 |
| 价格区原文含**销量关键词** | 价格可能取错（`已售/月销/人付款/评价/收藏`） |

AI 返回结果会被**格式校验**（正则 + 范围 0~999999），防幻觉；规范化去掉无意义尾随零（`128.0`→`128`、`19.90`→`19.9`）。AI 失败时自动回退本地结果。

### extractPrice 内部顺序（顺序很关键）

1. **先剔除销量/人气片段**（必须在去空格之前，否则 `¥ 5.00 592人付款` 去掉空格会变成 `5.00592人`，数字被粘连）
   - `已售592件`、`592人付款`、`月销592`、`1.02万+人付款`、`评价592`、`收藏592` …
2. **再去掉货币符号、千分位逗号、空白**（`¥` `￥` `,`）
3. **最后取第一个合法价格**（整数 1-5 位 + 最多 2 位小数，上限 999999）

## 🛠️ 侵权判定标准

### 五步核查

1. 标题含校名校徽关键词（`中国传媒大学` / `中传` / `CUC` / `校徽`）
2. 标识相同或近似
3. **作品/成果类 + 服务类排除**（命中即不侵权、不截图，见下）
4. **书籍/教材排除**（不在检测范围）
5. **其余一律判侵权** —— 非作品类、非服务类、非书籍，就直接判侵权（**不再要求命中商品类别词**）

> 📌 判定顺序：作品/服务类 → 书籍 → 默认侵权。前三项命中即终止。

### 🆕 默认判侵权规则（关键）

**只要标题含校名校徽关键词，且不是作品/服务类、也不是书籍，就一律判侵权。**

不再要求标题必须出现"徽章/笔记本/钥匙扣"等具体类别词。因此：

| 标题 | 判定 |
|---|---|
| `中国传媒大学 徽章 周边 纪念品` | ✅ 侵权（有类别词） |
| `中国传媒大学 纪念品` | ✅ 侵权（**无**具体类别词） |
| `中国传媒大学 文创` | ✅ 侵权（**无**具体类别词） |
| `中国传媒大学 定制` | ✅ 侵权（**无**具体类别词） |
| `中国传媒大学` | ✅ 侵权（仅校名） |
| `中国传媒大学 限量发售` | ✅ 侵权（**无**类别词） |

### ⚠️ 作品/成果类 + 服务类：命中即不侵权、不截图

**只要标题中出现任何作品/报告类词或服务类词，就直接判为不侵权，并跳过截图。**
不再做任何后续推断 —— **不根据标题里的"笔记本""明信片""徽章"等词去猜卖家真实意图。**

### 🔒 截图硬保护（关键修复）

**问题**：规则层已正确判定作品类/服务类"不侵权"，但 AI 增强层会**覆盖**该结论：

```
规则层 → return False, "作品商品（命中"实践作品"），不判侵权"
              ↓  (旧逻辑：非"标题不含校名校徽关键词"→ 仍触发AI)
AI层   → AI 判侵权 → return True     ← ❌ 作品类被"救活"
              ↓
主流程 → is_inf=True → 进入详情页截图  ← ❌ 作品类被截图
```

**修复**（三道防线）：

| # | 位置 | 措施 |
|---|---|---|
| 1 | `ai_verifier.py::ai_enhanced_judgment` | 新增 `FINAL_NEGATIVE` 终局性否定理由（`非实物产品` / `作品商品` / `服务商品` / `书籍` / `标题不含校名校徽关键词`）→ **直接返回规则结果，不调 AI** |
| 2 | `detector.py::is_suspected_infringement` | 作品/服务类排除**提到"商品类别匹配"之前**，命中即返回 |
| 3 | `detector.py` 主流程截图前 | **二次确认** `is_service_product(title)`，命中则 `continue` 跳过截图（兜底） |

> 修复后实测（模拟 AI 强制返回"侵权"）：
> 作品类 **15/15** 仍判不侵权且 `AI调用=False`；书籍 **4/4**；
> 其余默认判侵权 **12/12**；书籍误吞检查 **8/8**；终局性否定 **4/4**。
> 合计 **43/43** 通过。

### AI 判定同步约束

发给 DeepSeek 的判定 Prompt 中也写入了同样的规则：

- **先判断是否为实物**，是服务/作品/虚拟商品直接返回 `is_infringement: false`
- **特别提示**：即使标题中同时出现实物类词汇（如"笔记本""包""挂件"），只要核心交付物是**服务或作品/报告**，仍按不侵权处理——这些词只是描述作品的载体形式或制作方式

避免 AI 与本地规则结论冲突。
